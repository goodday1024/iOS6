# 部署、备份与回滚

## 初次部署

1. 复制 `.env.example` 并配置独立随机密码。管理员密码至少 12 位；在生产首次启动前启用 `ADMIN_TOTP_SECRET`（Base32）并在验证器里录入对应账号。不要上传 `.env`。
2. 执行 `docker compose up --build`，Web 与 API 同端口 8000。生产配置 TLS 反向代理，只对外公开 HTTPS；数据库与 Redis 不映射到公网。MinIO 使用独立受限应用账号代替 root 凭据。
3. 将 `S3_PUBLIC_ENDPOINT` 指向浏览器可访问的 HTTPS 对象存储，设置对应站点的 PUT CORS。桶不可公开读取。为 quarantine/ 前缀配置 1 天生命周期清理。
4. 获取 `/v1/keys` 的 publicKey，经可信渠道给宿主固定。私钥来自受限的 data/release-key.pem 或环境 RELEASE_KEY_BASE64；API 与 Worker 必须使用同一密钥。不要让 API 重建密钥后仍沿用旧客户端信任配置。
5. 健康检查 `/health`；API 文档 `/docs`。首次自建表，后续部署使用 Alembic。先备份，再运行 `python -m alembic upgrade head`。

当前采用模块化单体，API 用一个 Uvicorn worker。代码的请求频率限制在进程内；在多实例或公开服务中，需要网关/WAF 的共享限流。直传隔离文件也需要对象存储级配额。

## 账号与审核

ADMIN_EMAIL/ADMIN_PASSWORD 只在不存在该账号时创建管理员，不会覆盖既有密码。更改环境变量不会重置已创建账号。当前没有邮件验证、密码找回、开发者实名认证或自助 MFA 注册页面，运营环境应使用受控账号管理。

启用/更换 MFA 时，撤销旧管理会话（维护窗口中删除该管理员的 sessions），避免保留未验证的旧会话。TOTP 配置为整个管理域共用环境密钥，当前适用于单一受控管理员；多人审核生产部署需要逐用户 MFA 或外部身份服务。

审核员在 Connect 查看清单、权限、隐私和构建摘要后批准/拒绝，开发者仍须显式发布。审核后台尚未实现隔离的审核包试运行页面；审核员应在专用测试设备完成内容检查，不应只凭 manifest 批准。

## 数据备份

备份 PostgreSQL、MinIO 对象、签名私钥、环境密钥。仅备份数据库不能恢复应用包。默认 local 模式备份整个 `data/`，避免带入源码仓库。确保 AES-GCM 幂等记录的签名私钥也被备份，否则响应缓存不可解密。

```bash
# 运行时凭证来自容器环境，不把密码拼进命令参数。
docker compose exec -T postgres pg_dump -U retro retro6 > retro6-backup.sql
```

备份应加密并置于独立位置，定期在隔离环境恢复。不要执行 `docker compose down -v` 来更新，它会删除持久卷。

## 版本回滚

平台代码：还原先前镜像与源码，并检查迁移兼容性。第一版迁移只有初始建表；`alembic downgrade base` 会删除所有数据，不可作为线上应用回滚方式。

应用版本：发布只允许同版本或更高 SemVer；想撤销错误版本，先下架停止新下载，再把旧内容打包成更高版本上传、审核并发布。已安装的离线包不能被远程删除。

## 队列与清理

API 创建上传后才允许完成回调。队列任务使用固定 job id，处理事务可见性延迟时启用 RQ Retry。Worker 失败会记录 failed/error；测试者无法安装失败构建。队列状态不可用时完成回调返回 503，客户端可重试。

当前没有自动重驱所有因进程硬崩溃滞留 validating 的任务。运维应检查 RQ failed registry、上传状态和缺失对象，对完整隔离对象重新入队；否则标记失败并让开发者重新上传。对象清理与 RQ 作业状态应一起检查。

原生版本目录暂不自动 GC；频繁更新会保留旧包。可在后续版本加入“无活动会话且非当前版本”的垃圾回收。不要在运行会话仍引用旧版目录时直接删除。

## 尚未部署的能力

本工程不提供计费、推送通知、开发者实名认证、邮件服务、地区年龄策略、侵权申诉/举报工单、服务级 OpenTelemetry 或 SLO 告警。正式公开运营前应补齐这些需求并进行 WebKit、Docker/PostgreSQL/S3/Redis 及真实设备集成验收。
